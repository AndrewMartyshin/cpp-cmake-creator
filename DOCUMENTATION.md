# Техническая документация: C++ CMake Project Generator

## 1. Обзор архитектуры
Плагин разработан с использованием TypeScript и VS Code Extension API. Архитектура построена по событийно-ориентированному принципу. Код выполняется в изолированном процессе **Extension Host** (Node.js), что гарантирует стабильность основного интерфейса IDE даже при возникновении ошибок в логике плагина.

Взаимодействие с пользователем и файловой системой осуществляется асинхронно (`async/await`), за исключением операций записи файлов, где синхронные методы `fs` используются намеренно для упрощения кода и гарантии атомарности операций в рамках одного вызова команды.

## 2. Описание методов и компонентов

### `activate(context: vscode.ExtensionContext)`
**Назначение:** Главная точка входа (entry point) расширения. Вызывается средой VS Code при первом обращении к функциям плагина.
**Параметры:**
- `context`: Объект, предоставляющий доступ к метаданным расширения, путям и массиву `subscriptions` для управления жизненным циклом.
**Логика работы:**
1. Инициализирует `StatusBarItem` (элемент в нижней панели IDE) для быстрого визуального доступа к команде.
2. Регистрирует команду `extension.createCppCmakeProject` с помощью `vscode.commands.registerCommand`.
3. Добавляет все созданные объекты (status bar, disposable команды) в `context.subscriptions`, чтобы предотвратить утечки памяти при деактивации.

### Обработчик команды `extension.createCppCmakeProject`
**Назначение:** Реализация основной бизнес-логики создания проекта.
**Параметры:**
- `uri?: vscode.Uri`: (Опционально) URI-объект, передаваемый при вызове команды из контекстного меню проводника (указывает на выбранную папку).
**Этапы выполнения:**
1. **Сбор данных:** Запрашивает имя проекта через `showInputBox` (с валидацией на пустую строку) и стандарт C++ через `showQuickPick`.
2. **Разрешение пути (Path Resolution):** Определяет целевую директорию. Приоритет: выбранная папка в проводнике (`uri`) > корень текущего воркспейса > домашняя директория ОС (`os.homedir()`).
3. **Валидация и создание ФС:** Проверяет отсутствие папки через `fs.existsSync`. Создает директорию с флагом `{ recursive: true }`.
4. **Генерация шаблонов:** Использует шаблонные строки JavaScript (Template Literals) для динамической подстановки `${projectName}` и `${selectedStandard}` в текст `CMakeLists.txt`.
5. **Запись файлов:** Синхронно записывает `main.cpp` и `CMakeLists.txt` через `fs.writeFileSync`.
6. **Автоматизация (Бонус):** При согласии пользователя создает экземпляр `vscode.Terminal` и эмулирует ввод команд сборки (`cmake`, `make`) через метод `sendText`.

### `deactivate()`
**Назначение:** Функция очистки. Вызывается при отключении расширения. В данной реализации явная логика не требуется, так как VS Code автоматически обрабатывает все объекты, зарегистрированные в `context.subscriptions`.

## 3. Используемые структуры данных и API
- **Массивы:** `['C++11', 'C++14', 'C++17', 'C++20', 'C++23']` используется как источник данных (data source) для компонента `QuickPick`.
- **Объект `vscode.Uri`:** Применяется для безопасной работы с путями файловой системы, обеспечивая кроссплатформенную совместимость (Windows/macOS/Linux).
- **Модули Node.js:** 
  - `fs`: для операций создания директорий и записи файлов.
  - `path`: для корректного объединения путей (`path.join`), учитывающего разделители конкретной ОС.
  - `os`: для получения пути к домашней директории пользователя в качестве fallback-сценария.

## 4. Генерация HTML-документации (Опционально)
Данный код снабжен комментариями в формате **JSDoc**. Для генерации визуальной документации можно использовать утилиту TypeDoc:
1. Установить: `npm install -g typedoc`
2. Запустить в корне проекта: `typedoc src/extension.ts`
3. Результат будет доступен в папке `docs/`.
